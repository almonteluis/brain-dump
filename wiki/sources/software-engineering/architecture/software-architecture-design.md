# Software Architecture and Design

**Source:** raw/02_reference/software-engineer/Architecture/Patterns/Software Architecture and Design.md
**Date ingested:** 2026-04-09
**Type:** technical reference

## Summary

Software architecture is the foundational organization of a system, serving as a blueprint for developers. It defines structure, behavior, and relationships between components during the design phase of SDLC.

## Key Claims

- Architecture represents the underlying organization of the system
- Early design decisions are costly to change once implemented
- Well-architected systems last longer and reduce technical debt
- Architecture drives deployment and infrastructure decisions

## Why Architecture Matters

1. **Communication** — Creates shared language among team members
2. **Early Design Decisions** — Critical choices before resources committed
3. **Flexibility** — Supports adaptation to changing requirements
4. **Increases Lifespan** — Well-architected systems last longer

## Common Architectural Patterns

| Pattern | Description |
|---------|-------------|
| Layered Architecture | Horizontal layers with specific responsibilities |
| Microservices | Small, independent services with single responsibility |
| Event-Driven | Components communicate through events |
| Client-Server | Separates providers and consumers |
| MVC | Model-View-Controller separation |

## Best Practices

1. Start with clear requirements
2. Choose the right architectural style
3. Document thoroughly
4. Consider scalability from the start
5. Plan for evolution
6. Apply security by design
7. Validate with stakeholders
