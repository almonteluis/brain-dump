# Good Software Knows When to Stop

**Source:** Good software knows when to stop.md
**Date ingested:** 2026-04-29
**Type:** Essay

## Summary

Olivier Girardot uses satire ("AI-Powered Directory Intelligence™" replacing `ls`) to argue that good software knows its purpose and resists feature bloat. Cites 37Signals principles from *Rework* and *Getting Real*.

## Key Claims

- Good software knows the problem it solves and what needs to be tackled by another tool
- Satirical example: `ls` replaced by "Adaptive Listing System™" with AI predictions, rankings, and 30-day deprecation notice
- Being de facto standard for a given problem has more value than rebranding as the "new hot thing"
- References Minio → AIStor, Oracle Database → "Oracle AI Database" as examples of unnecessary rebranding

### 37Signals Principles

- **Constraints are advantages** — small teams, tight budgets, limited scope force better decisions
- **Ignore feature requests** — don't build what users ask for; understand underlying problem
- **Ship early, ship often** — half-product that's real beats perfect product that's vaporware
- **Epicenter design** — start with core interface/interaction, not edges (nav, footer)
- **Say no by default** — every feature has hidden cost: complexity, maintenance, edge cases
- **Scratch your own itch** — build something you need; you'll make better decisions
