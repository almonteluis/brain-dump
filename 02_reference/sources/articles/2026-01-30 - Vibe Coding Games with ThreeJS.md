# Vibe Coding Games with ThreeJS

> With Opus 4.5 & GPT 5.2 - Claude Code / Codex CLI have much better end results now. I can say that leap in building games with vibe coding is real.

## 🎯 Why This Matters
This tweet demonstrates that building games through "vibe coding" (prompting AI to build) is now viable, especially with ThreeJS. The key insight is progressive skill improvement: each game built updates the skill, making it better for the next game. This creates a compounding learning loop.

## 📋 Key Insights

### Insight 1: ThreeJS Skill is the Key Unlock
The critical component for vibe coding games is ThreeJS expertise. Without ThreeJS knowledge, the workflow doesn't work. With it, you can guide AI agents effectively.

**Implication:** ThreeJS is the bottleneck, not AI capabilities. Learn ThreeJS basics, then leverage AI for implementation.

### Insight 2: Progressive Skill Improvement Through Bugs
The workflow isn't "build one game and done." It's iterative: build → play → find bugs → update skill → build next game (better).

**How it works:**
1. Build a game with current skill
2. Play it, identify bugs or issues
3. Update skill based on what went wrong
4. Next game builds on improved skill

**Result:** Skill progressively gets better at building the gameplay you want.

### Insight 3: Multi-Agent Workflow Beats Single Agent
Combining multiple AI agents produces better results:
- **Claude Code / Codex Agent:** For coding implementation
- **Nano Bana Pro:** For game design + technical design specs
- **Opus 4.5 / GPT 5.2:** For better end results (implied for creative or complex tasks)

**Why it works:** Each agent specializes. You get better design (Nano Bana), better code (Claude Code/Codex), better results overall (Opus/GPT).

### Insight 4: Vibe Coding Games is Now Real
Past: Vibe coding games was theoretical or produced low-quality results.

Present: With ThreeJS + multiple AI agents + progressive improvement, "leap in building games with vibe coding is real."

**Evidence:** Author built 4 playable games in one week:
- Endless runner
- Tower defense
- Mario Party-like mini-game
- Arena-based shooter

### Insight 5: Sharing Skills Accelerates Community
The author shares skills + source code + playable links. This allows the community to learn from their iterative improvements rather than starting from zero.

## 💡 New Concepts

### Concept: Vibe Coding Games
Building games by prompting AI to implement features, mechanics, and systems based on descriptions or conversations, rather than writing all code manually.

**Why it matters:** Makes game development accessible to people without full game engine knowledge, if they understand basics (like ThreeJS) and can guide AI effectively.

**When to use:** When you want to prototype games quickly, experiment with mechanics, or build small-scale games.

### Concept: Progressive Skill Improvement
Updating your AI prompting skill (or skill files) based on bugs, issues, or lessons learned from each project, so the next project benefits from that knowledge.

**Why it matters:** Creates a compounding learning loop. Each project teaches you (and your skill) how to be better at the next.

**When to use:** For any repetitive creative or technical work where patterns emerge across projects.

### Concept: Multi-Agent Game Dev Workflow
Using different AI agents for different aspects of game development (design, coding, testing, optimization) to get better results than any single agent alone.

**Why it matters:** Each agent specializes. You get better design from design agent, better code from coding agent, etc.

**When to use:** Complex games or when single-agent results are mid.

## 🔗 Frameworks & Patterns

### ThreeJS Game Vibe Coding Workflow

**Description:** Step-by-step process for building games through vibe coding with ThreeJS and multiple AI agents.

**How to apply:**
1. **Learn ThreeJS basics** (prerequisite)
2. **Design game concept** (use Nano Bana Pro for game design + technical specs)
3. **Code with AI agents** (Claude Code / Codex for implementation)
4. **Play and debug** (identify bugs, issues, improvements)
5. **Update skill** (refine prompting based on what went wrong)
6. **Repeat** (next game builds on improved skill)

**Tools used:**
- ThreeJS (3D rendering)
- Claude Code / Codex Agent (coding)
- Nano Bana Pro (game design + technical specs)
- Opus 4.5 / GPT 5.2 (better end results)

**When to use:** When building games through vibe coding approach.

**Expected progression:**
- First game: Slow, lots of bugs
- Second game: Better, fewer bugs
- Third game: Solid results
- Fourth game: Good enough to share

### Game Design Document Creation

**Description:** Using TinyPRD's Game Mode to create structured game design documents.

**How to apply:**
1. Use TinyPRD's Game Mode
2. Create game design document (mechanics, story, levels, systems)
3. Reference document when prompting AI for implementation

**Why it works:** Structured docs give AI clear requirements (Layer 2 of 5-Layer Prompt Architecture: Context).
